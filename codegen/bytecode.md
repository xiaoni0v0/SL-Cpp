# 字节码与虚拟机设计

`codegen/`（AST → `Code`）和 `executor/`（跑 `Code`）之间的契约。这里的一切都不是 SL 的可观察行为
——换一套指令集不改变任何 SL 程序的行为，所以不进 `SL.md`；涉及语义处一律以 `SL.md` 为准。

## 整体模型

- 帧栈。每个帧持有自己的操作数栈、一个 `Code`、一个指令计数器。
- 主循环取栈顶帧的下一条指令执行。压帧（`CALL`/`MAKE_CLASS`/`EVAL`）只是换栈顶，主循环不递归；被压的
  帧结束时由自己的 `RETURN_VALUE` 把结果压回下面那帧的操作数栈。
- 一个 `Code` 对应一个帧的边界：一份文件、一个函数体、一个类体各一个 `Code`。

**两处不由主循环压帧**：`import` 的加载算法、内置函数回调 SL 函数。这两处允许在实现内部递归启一轮子
循环跑完再返回——摊成字节码会把它们变成状态机，不值。代价是吃 C++ 调用栈，跟 `RecursionError` 的
guard 一起管。

**`eval` 是"`Code` 边界 = 帧边界"的唯一例外**：编译出的是单条表达式的 `Code`，压出来的帧执行状态是
自己的、**名字环境指向调用帧**（下面的 `env_`）。"等价于没有新帧"由此落地，压帧规则本身没开洞。

**局部变量走字典查找，不能编译成槽位下标**：`_L` 恒为真字典，`eval` 能往任意帧现插代码。将来的槽位化
条件见 `.ai/context.md`，本设计不预留接口。

## 指令编码

一条指令固定 2 字节：高字节操作码、低字节参数，无参指令塞 0。实现上就是 `std::vector<std::uint16_t>`，
计数器是它的下标——"偶数个字节"由类型本身保证。**跳转目标一律绝对、以指令为单位**（即计数器的值），
不是字节偏移。

**`EXTENDED_ARG`**：8 位参数不够用（常量表下标、跳转目标、参数个数都会超）。前缀 `EXTENDED_ARG a` 把
待用参数累积成 `(已累积 << 8) | a`，可连用，最多 4 条，只对紧随其后的那条真指令有效。加前缀会让后面
所有指令下标右移、可能又逼出新前缀，所以 codegen 先产出带标签的伪指令流，再反复扫描到不再变化为止
（前缀只增不减，必收敛）。

## `Frame` 存什么

执行状态（每帧独有，`eval` 帧也独有）：

| 字段      | 内容                                                |
|-----------|-----------------------------------------------------|
| `code_`   | 正在执行的 `Code`（不拥有，由函数对象/模块持有）    |
| `pc_`     | 指令计数器，单位是指令                              |
| `stack_`  | 操作数栈，容量按 `Code` 里的栈深上限一次分配        |
| `blocks_` | 块栈：异常处理器的展开信息，见下面 try/finally 一节 |

名字环境：

| 字段             | 内容                                                                                              |
|------------------|---------------------------------------------------------------------------------------------------|
| `env_`           | **名字环境所在的帧**。普通帧指向自己；`eval` 帧指向调用帧。下面四个字段一律经由 `env_` 访问       |
| `locals_`        | 局部字典对象的引用，即 `_L`。帧死亡时置为 `None`（不是清空、不是换对象），判活就看它是不是 `None` |
| `globals_frame_` | 所属全局帧。全局帧指向自己——**帧靠 `globals_frame_ == this` 自判是不是全局帧**，不另设标志位      |
| `global_marks_`  | global 标记集，一组名字                                                                           |
| `owner_`         | 建立这一帧的东西：函数对象 / 类构建器 / 模块对象；`eval` 帧为空                                   |

`owner_` 一个字段兼三件事，不用再开字段：**定义帧**从它身上取（函数对象和类构建器都记着，引用捕获据此
路由）；**`RETURN_VALUE` 的收尾**按它的种类分派（函数对象 → 返回值类型检查后压回调用帧；类构建器 →
丢弃值、收属性、算 MRO/`__abstractmethods__`、造出类对象压回；模块对象 → 记进 `__return__` 或当退出
码）；返回类型注解和形参注解（`TypeVar` 一致性检查要用）也在它身上。

**引用捕获名集合不在帧上，在 `Code` 上**——同一份 `Code` 捕获的名字必然相同，每帧存一份是重复。取的
时候走 `env_->code_`，`eval` 帧因此自动用上调用帧的捕获集合。

## `Code` 存什么

| 字段           | 内容                                                                                                     |
|----------------|----------------------------------------------------------------------------------------------------------|
| 字节码         | 见上                                                                                                     |
| 常量表         | 字面量对象、名字字符串组成的元组（`CALL_KW` 用）、**嵌套 `Code`**（函数体/类体）                         |
| 名字表         | 标识符、属性名、`import` 的点分名字                                                                      |
| 栈深上限       | 编译期算出，用来一次性分配操作数栈                                                                       |
| 引用捕获名集合 | 函数体/类体 `Code` 才有。**必须持久保留**：运行期每次按标识符读写都要查"这个名字是不是引用捕获"          |
| 形参形状       | 函数体 `Code` 才有：四段形参各自的名字表、哪些有默认值/注解、`*args`/`**kwargs` 的名字。实参绑定算法吃它 |
| 行位置表       | 指令下标 → 源码行列，外加来源标识（文件名 / `<eval>`）。纯为报错，非规范                                 |

**明确不进 `Code`**：装饰器（建立完对象之后的独立步骤，是外层 `Code` 里的普通调用指令）；形参默认值、
各类注解、`doc`、函数名（都在外层作用域、建立时求值，挂到函数对象上，`Code` 只需知道"有没有"，而这
已经在形参形状里）；值捕获（同上，调用时随实参写进 `_L`）；容器字面量的**值**（`(1, 2)`、`[1]`、
`{1: 2}` 一律运行期构造——进常量表等于让两次求值拿到同一个对象，把 `is` 的结果钉成实现细节）。

decimal 字面量反而**可以**进常量表：按字符串精确构造，不受上下文 `prec`/`rounding` 影响，跟"结果为
decimal 的运算一律不折叠"不矛盾，后者禁的是**运算**。

`Code` 对 SL 完全不可见，不通过 `getattr`/`attrs()` 暴露——暴露就等于把字节码格式变成可观察行为。

## 栈约定

- **每条表达式求值完，在操作数栈上恰好留一个值**，整个 codegen 靠这条组合。值恒为 `None` 的纯副作用
  构造（`del`/`global`/`break`/`continue` 等）由 codegen 在指令后补一条 `LOAD_CONST None`。
- 赋值类指令一律**弹光**自己的操作数、不留值；需要赋值表达式的值时由 codegen 垫一份（见下面的模式）。
- codegen 必须静态跟踪每个点的栈深：算栈深上限要用，`break`/`continue` 的裁栈也要用。

## 指令表

参数写作 `n`/`i`/`t`：`n` 是个数或表下标，`t` 是跳转目标。栈的写法一律**左边是栈底**。

### 栈与常量

| 指令             | 行为                                                    |
|------------------|---------------------------------------------------------|
| `EXTENDED_ARG a` | 给下一条指令的参数补高 8 位，可连用                     |
| `POP_TOP`        | 弹掉栈顶                                                |
| `COPY i`         | 把从栈顶数第 `i` 项（`i=1` 即栈顶）复制一份压栈         |
| `INSERT n`       | 弹出栈顶，插回到深度 `n` 的位置（`n=2` 即交换栈顶两项） |
| `LOAD_CONST n`   | 压常量表第 `n` 项                                       |

### 名字

以下"按作用域规则"指：名字在 global 标记集里就作用于 `_G`，是引用捕获就转发到**定义帧**（定义帧的
局部字典已是 `None` 则 `NameError`），否则作用于 `_L`；读取时 `_L` → `_G` → 内置表逐级退回。

| 指令               | 行为                                                                                                                          |
|--------------------|-------------------------------------------------------------------------------------------------------------------------------|
| `LOAD_NAME n`      | 按作用域规则读名字表第 `n` 项，查不到 `NameError`                                                                             |
| `LOAD_NAME_AUG n`  | 复合赋值读旧值专用：不在 global 标记集时**只查 `_L`**、不退回 `_G`/内置表，查不到 `NameError`。保证这次读和随后的写落在同一帧 |
| `STORE_NAME n`     | 弹栈顶，按作用域规则写                                                                                                        |
| `DELETE_NAME n`    | 按作用域规则删，不存在 `NameError`                                                                                            |
| `DECLARE_GLOBAL n` | `global identifier`：名字是引用捕获则 `NameError`；已在标记集则跳过；否则删掉 `_L` 里的同名项、把名字加进标记集               |
| `LOAD_LOCALS`      | 压 `_L` 字典对象本体（不是视图、不是快照）                                                                                    |
| `LOAD_GLOBALS`     | 压 `_G`                                                                                                                       |

### 属性与索引

| 指令            | 行为                                                                     |
|-----------------|--------------------------------------------------------------------------|
| `LOAD_ATTR n`   | `obj` → 属性值                                                           |
| `STORE_ATTR n`  | `obj val` → 弹两项，写属性                                               |
| `DELETE_ATTR n` | `obj` → 弹掉，删属性                                                     |
| `GET_INDEX n`   | `obj a1 … an` → 结果，走 `__op_get_index__`                              |
| `SET_INDEX n`   | `obj a1 … an val` → 弹光，走 `__op_set_index__`                          |
| `GET_INDEX_EX`  | `obj args` → 结果。`args` 是下标已打包好的 list，索引里出现 `*` 展开时用 |
| `SET_INDEX_EX`  | `obj args val` → 弹光                                                    |

### 运算符

| 指令                    | 行为                                                                                                                                          |
|-------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------|
| `UNARY_OP op`           | `x` → 结果。`op` 选 `+` `-` `~` `not` `?` `!`                                                                                                 |
| `BINARY_OP op`          | `x y` → 结果。`op` 选全部二元运算符，含六个比较、`in`、`is`、`..`。正向/反向方法、`__op_cmp__` 回退、`==`/`!=` 的身份兜底全在这条指令的实现里 |
| `CMP_CHAIN op`          | 链式比较的非末段：`x y` → `y t`，`t` 是 `x op y` 的结果，`y` 留在下面供下一段用                                                               |
| `JUMP_IF_FALSE_CHAIN t` | 配合上一条：栈顶是 `t`、下面是 `y`。`t` 真值为假 → 弹掉 `y`（留 `t`）跳 `t`；为真 → 弹掉 `t`（留 `y`）继续                                    |

`and`/`or` 不是 `BINARY_OP`，走短路跳转。

### 容器

| 指令                                              | 行为                                                                                                                                      |
|---------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------|
| `BUILD_TUPLE n` / `BUILD_LIST n` / `BUILD_DICT n` | 弹 `n` 项（dict 弹 `2n` 项、键值交替）建容器。无展开项时用这组                                                                            |
| `LIST_APPEND`                                     | 弹栈顶，追加到下面的 list                                                                                                                 |
| `LIST_EXTEND`                                     | 弹栈顶（要求可迭代，否则 `TypeError`），元素依次追加到下面的 list                                                                         |
| `DICT_PUT`                                        | 弹 `k v` 两项写入下面的 dict                                                                                                              |
| `DICT_MERGE`                                      | 弹栈顶（要求满足映射协议，否则 `TypeError`），各项并入下面的 dict                                                                         |
| `LIST_TO_TUPLE`                                   | 把栈顶的 list 换成 tuple                                                                                                                  |
| `UNPACK n`                                        | 弹栈顶（要求可迭代），**逆序**压入各元素使第一个元素在栈顶；个数不是 `n` 则 `ValueError`                                                  |
| `UNPACK_EX a`                                     | 带 `*lv` 的解构：`a` 低 8 位是星号前的项数、高 8 位是星号后的项数（高位靠 `EXTENDED_ARG` 给出）。星号项绑一个 list；元素不够 `ValueError` |

带 `*`/`**` 展开的元组/列表/字典字面量走 `BUILD_LIST 0` / `BUILD_DICT 0` 加逐项
append/extend/put/merge，元组最后补 `LIST_TO_TUPLE`；收集模式的 `for` 复用同一组指令。

### 跳转

| 指令                     | 行为                                                                |
|--------------------------|---------------------------------------------------------------------|
| `JUMP t`                 | 无条件跳                                                            |
| `POP_JUMP_IF_FALSE t`    | 弹栈顶，真值为假则跳。真值即 `__bool__`，返回非 bool 是 `TypeError` |
| `JUMP_IF_TRUE_OR_POP t`  | 真值为真：**保留**栈顶并跳；否则弹掉继续。`or` 用                   |
| `JUMP_IF_FALSE_OR_POP t` | 真值为假：保留栈顶并跳；否则弹掉继续。`and` 用                      |
| `GET_ITER`               | 栈顶换成它的迭代器，不满足可迭代协议则 `TypeError`                  |
| `FOR_ITER t`             | 栈顶是迭代器：取到下一个元素就压栈；耗尽则弹掉迭代器并跳 `t`        |

### 异常与 finally

块栈的一项记 `{处理器目标, 进块时的操作数栈深}`。异常传播时：从当前帧块栈弹出最近一项，把操作数栈裁到
它记的深度，压入异常对象，跳到它的处理器；块栈空了就弹帧、继续往下一帧传播。

| 指令                                 | 行为                                                                                      |
|--------------------------------------|-------------------------------------------------------------------------------------------|
| `SETUP_EXCEPT t` / `SETUP_FINALLY t` | 压一项块                                                                                  |
| `POP_BLOCK`                          | 弹一项块（正常路径走完 try 体时）                                                         |
| `CALL_FINALLY t`                     | 把"返回地址"压栈并跳到 `t`。正常完成、`return`/`break`/`continue` 经过 `finally` 时走这条 |
| `END_FINALLY`                        | 弹栈顶：是返回地址就跳回去；是异常对象就继续向外传播                                      |
| `CHECK_EXC_MATCH`                    | `exc E` → `exc bool`，弹掉 `E`、压 `isinstance(exc, E)`                                   |
| `RAISE`                              | 弹栈顶并抛出；不是 `BaseException` 的实例则 `TypeError`                                   |
| `RERAISE`                            | 弹栈顶异常对象，继续传播（不产生新的位置信息）                                            |

"返回地址"是纯内部的整数值，SL 层拿不到，只在 `finally` 体执行期间待在操作数栈上。

### 调用与建立

| 指令           | 行为                                                                                                                                                           |
|----------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `CALL n`       | `f a1 … an` → 建局部帧压栈。只有位置实参                                                                                                                       |
| `CALL_KW n`    | `f a1 … an names` → 同上。`names` 是常量表里的名字元组，末尾 `len(names)` 个实参按名字传                                                                       |
| `CALL_EX`      | `f args kwargs` → 同上。实参里有 `*`/`**` 展开时用，`args` 是 list、`kwargs` 是 dict                                                                           |
| `MAKE_FUNC`    | 弹 6 项建函数对象，见下                                                                                                                                        |
| `MAKE_CLASS`   | 弹 5 项，新建局部帧执行类体，见下                                                                                                                              |
| `RETURN_VALUE` | 弹本帧栈顶作为值，弹帧，按 `owner_` 的种类收尾                                                                                                                 |
| `IMPORT_KW n`  | 关键字形态 `import a.b.c`：名字表第 `n` 项是完整点分名，按加载算法执行，压入**第一段**的模块对象                                                               |
| `IMPORT_CALL`  | 调用形态：`args kwargs` → 模块对象。实参绑定同普通调用，压入**最后一段**的模块对象                                                                             |
| `EVAL`         | `args kwargs` → 绑出 `code`（绑定失败 `DispatchError`，非 str 则 `TypeError`），解析成恰好一条表达式（否则 `SyntaxError`），编译，压一个名字环境指向当前帧的帧 |

实参与形参的绑定算法（槽位填充、`*args`/`**kwargs` 收集、类型检查、函数族逐个试）不摊成字节码，是
`CALL` 系列指令实现内部的事。`IMPORT_CALL`/`EVAL` 固定走打包好的 `args`/`kwargs` 形状，不配快路径——
两者都不是热点。`EVAL` 编译 `code` 时交给语义检查的 `in_local_scope` 取 `globals_frame_ != this`，这是
`global` 在 `eval` 里合不合法的唯一依据。

## 关键构造的 codegen 模式

**链式比较 `a < b < c`**（`is` 链同理）。末段用 `BINARY_OP`，不需要再留操作数；多于两段就重复中间那行：

```
<a> <b> CMP_CHAIN Lt   JUMP_IF_FALSE_CHAIN end
<c> BINARY_OP Lt
end:
```

**赋值表达式的值**：赋值指令不留值，需要值时先垫一份再让指令弹光。

```
x = e         : <e> COPY 1 STORE_NAME x
x.a = e       : <x> <e> COPY 1 INSERT 3 STORE_ATTR a
x[i] = e      : <x> <i> <e> COPY 1 INSERT 4 SET_INDEX 1
(a, b) = e    : <e> COPY 1 UNPACK 2 STORE_NAME a STORE_NAME b
```

**复合赋值**：目标只求值一次，靠 `COPY` 复制已在栈上的那份。多下标的用 `n+1` 条 `COPY n+1` 把 `obj`
和各下标整体复制一遍。

```
x op= e       : LOAD_NAME_AUG x <e> BINARY_OP op COPY 1 STORE_NAME x
x.a op= e     : <x> COPY 1 LOAD_ATTR a <e> BINARY_OP op COPY 1 INSERT 3 STORE_ATTR a
x[i] op= e    : <x> <i> COPY 2 COPY 2 GET_INDEX 1 <e> BINARY_OP op COPY 1 INSERT 4 SET_INDEX 1
```

**循环**：进循环前先压**结果槽**（计数模式压 `0`，`$` 压空 list，`$$` 压空 dict），它整个循环期间待在
栈上，循环结束时就是整条表达式的值。循环体求值后栈上多一个值，每轮收尾把它并进结果槽：

```
计数模式   : POP_TOP LOAD_CONST 1 BINARY_OP Add
$         : LIST_APPEND
$ *       : LIST_EXTEND
$$        : UNPACK 2 INSERT 2 DICT_PUT
$$ **     : DICT_MERGE
```

**`break`/`continue` 不用运行期的块栈**：跳到哪、裁掉几层操作数栈，codegen 静态就知道（它本来就在跟踪
栈深），编译成"若干 `POP_TOP` + `JUMP`"；中间隔着 `finally` 时在跳之前由内到外补 `CALL_FINALLY`。
`return` 同理，只是不用裁栈（弹帧时整个操作数栈一起没了），返回值在 `finally` 体执行期间待在栈上不受
影响——`finally` 体是栈中性的。

**`try`**：

```
SETUP_EXCEPT h    <expr1>   POP_BLOCK   JUMP after
h:  COPY 1 <E1> CHECK_EXC_MATCH POP_JUMP_IF_FALSE next1
    (有 as 就把栈顶异常对象赋给 lvalue，否则 POP_TOP) <expr2> JUMP after
next1: …          RERAISE
after:
```

`finally` 在外面再包一层 `SETUP_FINALLY`：正常路径走完后 `POP_BLOCK` + `CALL_FINALLY`，异常路径由 VM
展开时直接跳进同一段 `finally` 体，末尾统一 `END_FINALLY` 分派——**`finally` 体只编译一份**。语言禁止
`finally` 体里跳出这段范围，编译期就查掉了，所以这里不用处理"跳转穿过 `finally`"。

**建立函数**：装饰器必须最先求值，所以先压装饰器；`Code` 和名字是常量、没有副作用，放最后压不影响顺序。

```
<deco1> … <decoN>
<各值捕获> BUILD_TUPLE k
<各形参注解/默认值> BUILD_TUPLE m
<返回类型> <doc> LOAD_CONST <Code> LOAD_CONST <名字>
MAKE_FUNC
CALL 1  (由近到远，一个装饰器一条)
COPY 1 STORE_NAME f   (命名函数才有，绑定只发生一次、绑最终值)
```

`MAKE_FUNC` 固定弹 6 项——弹几个必须编译期确定，不能运行时先查元信息才知道弹多少。缺的注解/默认值/
名字/`doc` 一律压一个**纯内部的哨兵值**（不能拿 `None` 顶替，`None` 本身是合法默认值）。引用捕获不产生
任何指令：`MAKE_FUNC` 就在当前帧里执行，天然知道定义帧是谁，直接抓一份引用挂到新对象上。

**建立类**：形状同上，基类元组代替形参那段，弹 5 项。`MAKE_CLASS` 不直接产出类对象——它新建局部帧、
写入值捕获、压栈执行类体；类体的 `RETURN_VALUE` 收尾时才由 `owner_`（类构建器）完成属性收集、MRO、
`__abstractmethods__`，把类对象压回。装饰器调用在这之后。

**同一份 `Code` 可以复用多次，但"建立"每次都必须造出全新的函数/类对象**——`is` 比的是对象身份，循环里
的值捕获必须各自捕获当次的值。

## 明确留给以后

- 窥孔优化、超级指令、内联缓存：一概不做，先要正确。
- 局部变量槽位化：前提是"这份 `Code` 里有没有 `eval` 点"的静态判定，等有性能需求再说。
- 异常表取代块栈（把 try 的运行期开销降到零）：等块栈真成为瓶颈再换，对 codegen 之外不可见。
- `RecursionError` 的深度阈值：帧栈深度和 C++ 调用栈深度是两件事，两个都要 guard，阈值未定。
